# 派工与验收 · 执行 Agent 使用铁律

> 出处：数月真实派工实战。**这些不是理论，每一条都对应一次产出丢失或检验空气。**

---

## 一、先记住执行 Agent 的三个特性（它们决定怎么写工单）

1. **它只做事不回话。** 执行完不向你复述过程。
   → 成果**必须写死落盘到约定文件**，绝不能靠「它在对话里贴出来」。
2. **它可能静默不执行或中途失败。** 给了工单 ≠ 它执行了；卡住或失败也不报。
   → 必须有**分步落盘的中间标记**，让你一读文件就知道它走到哪一步。
3. **它常与你共享文件系统。** 落点用绝对路径钉死，它写哪你读哪。

---

## 二、每张工单必含（**缺一即可能产出丢失 / 无法检验**）

- [ ] **落点钉死**：源文件 / 产出文件 / 回执文件，全部写死**绝对路径**。
      明令「不许用相对路径、不许自选落点、产出不许落指定目录以外」。
      ⚠ 相对路径 → 它在自己的工作目录执行，产出落在你读不到的地方。
- [ ] **写入方式钉死**：明确用哪个工具写。写错工具 = 写进它自己的沙箱，外面找不到。
- [ ] **分步落盘中间标记**：每完成一步写一个标记/证据进回执文件。
- [ ] **回执即证据**：完工证据（计数、语法检查结果、落点行号、sha256）写进固定路径。
- [ ] **停止条件**：预算上限 / 轮数上限 / 连续同类失败即停。
- [ ] **红线清单**：哪些文件一个字都不许动，写死。
- [ ] **要求它写「我不确定的地方」**，并注明**这一条最重要**。
- [ ] 测量类任务必须写死「**一条判据都不许改**」——否则它会顺手优化，测量就废了。

### 不要做的

- ⛔ **不让它整体重写大文件**（撑爆上下文 + 极慢）。用逐段替换。
- ⛔ 不给开放式任务（「优化一下」）。给可判真假的完工判据。

---

## 三、验收（**绝不凭「它说做完了」**）

```
1. 先 list 落点目录，确认产出真的存在   ← 不做这步就是在检验空气
2. 读回执文件                          ← 它自称做了什么
3. 读产出文件本身                      ← 它实际做了什么
4. 独立复算关键数字（用真函数/真工具重跑一遍，不抄它的结论）
5. 跑回归，确认没打坏别的
6. 核红线：用 mtime / git status 扫全库，看有没有动不该动的文件
```

⚠ **第 4 步和第 6 步是审计的价值所在。** 前三步执行方自己也会做；
**审的人不能和写的人共用同一套假设**——执行方验的是「我做的对不对」，
你要验的是「我们是不是在量对的东西」。

⚠ **对照的粒度必须细到与被测的判定单元同级。** 节点级对照会放过题级的 bug。

---

## 四、产出找不到时的探针（不要瞎猜，跑这个）

让它做三件事，全部写死绝对路径：
1. 读一个**已知存在**的文件的前几行
2. 列出它自己的可写目录
3. 把上面两条的结果 write 到 `<你指定的绝对路径>/probe_result.txt`，然后读回确认

**你去读那个文件**：
- 读到 → 共享盘且它能执行 → **说明它上次根本没执行，重派**
- 读不到 → 未执行或不共享盘 → **换交接方式**，别再重派同一张工单

---

## 五、回炉循环

不妥之处 → 带着**具体问题 + 原文行号**回炉 → 再检验 → 循环，直到满意。
⛔ 不要自己动手把它的活干了——那样下次它还是那样。**把缺口写清楚让它修，是在训练接口，不是在做题。**

---

## 六、工单模板骨架

```markdown
# 施工指令 · <批次号>（新窗口 · 自包含）

## 0 · 本批要回答/交付的是什么（一句话，可判真假）
## 1 · 红线（碰即停）：只允许改 X/Y；不许动 A/B/C/任何回归期望值
## 2 · 上下文纪律：不整体重写大文件 / 不 cat 超 300 行 / 长跑加 -u
## 3 · 任务（每个任务：做什么 / 落点绝对路径 / 记什么 / 判读）
## 4 · 停止条件（预算上限 / 轮数 / 回归必须全绿）
## 5 · 报告格式（正面回答 + 数据表 + 记进待办的 + **我不确定的地方**）
⛔ 本批只测量/只施工，处置由人看完数据再定
```
