## 每次开工前的固定五步（**不要跳，跳了就是在为过程而过程**）

```
0. 【证据】头：本轮第一个动作是读真实状态，不是回忆
1. 守常：读项目的法典/准则文件（锢不在脑子里，在文件里）
2. 拿真值：跑状态生成器；没有生成器就直接读真源，不读人写的完成度表
3. 对齐：先看最近的实际记录，再用索引导航（防滞后快照陷阱）
4. 观象：一句话判两问 —— 时位（这步在什么阶段、该潜还是该飞）+ 向果（服务终极目标哪一条）
         ⛔ 两者都不是 → 停，这步可能在偏
```

## 每次收工前的固定四步

```
1. 销账：回状态源把已完成项标死（落盘与销账是一个动作的两半，没销账 = 没闭环）
2. 生核：教训生进法典/核心规则，不记成流水账
3. 标期：C 类一次性过程标到期
4. 交接：更新「在建」与「交接」，让下一个人接得上
```

## 最容易犯的六个错（**每次都要自查**）

1. **在非约束处使劲。** 自查：「这一环再好十倍，终极指标会动吗？」不会 → 它不是约束。
2. **用过程量当完工判据。** 良率/通过率永远能再优化一轮，这种循环在结构上关不掉。
3. **拿人写的状态当真值。** 它写完当天就可能过期，而且不会报错。
4. **量具没合格就出读数。** 判定工具先过三关：重复性 / 再现性 / **分辨力**（能分档数 <3 基本只是个开关）。
5. **只做验证不做确认。** 只做验证的项目可以一路全绿地做出一个没人需要的东西。
6. **凭滞后快照推断出一个「问题」，然后一头扎进真实环境刨去验证它。** 答案常常就在最近的记录里。

## 边界

- 简单问答、查一个值、改一行 → 不必走全流程，但仍守三条永不豁免。
- 判据：**这个任务值不值得画一张施工图？** 值得 → 走全流程。
- ⛔ **任何重组、清理、批量修改之前，先确认有回滚点。**
- ⛔ **最贵的那个修复动作之前，先证伪它对应的假设。**
