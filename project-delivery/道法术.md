## 序 · 这套方法论到底解决什么问题

它不是「怎么写代码」，也不是「怎么管进度」。它解决的是一个更根本、更少被正视的问题：

> **如何跟一个「没有持久记忆、天生会幻觉出确定感、能悄悄改坏文件、不能被信任去执行不可逆动作」的 AI 协作，把一个「真金白银、真生产系统、大量不可逆动作」的复杂项目稳稳建起来。**

只要你的项目具备下面任意几条，这套方法就适用：跨越很多个断续的对话窗口、AI 每次都是「失忆重启」；有不可逆动作（部署 / 删改 / 外发 / 打钱 / 动生产库）；事实分散在很多文件里、会膨胀会过期会自相矛盾；需要人 + AI + 落地执行者多方配合。

**V1.3 起，它同时覆盖工作的两个半边**：既管「把已定的事做对」（收敛 / 执行），也管「找到并验证该做什么」（发散 / 探索）——两半用不同的模式跑，见下方「模式开关」。

## 道 · 一根

> **不执方，而执时；守不易之道为锢。**
> **任务必闭环，大脑常生长——事事有终，而生生不息。**

方法不是刻死的招式，刻死招式本身就是「锢」。锢不在脑子里，在文件里：**动手前先读项目的准则文件，不凭记忆。**

整套方法论只锁死两个动词：**闭环**（每个任务有一个「被实证过的终止态」，不是「大概做完了」）与**生长**（规则大脑持续吸收教训、也持续淘汰过期物，越用越准而不是越用越肿）。下面的「法」和「术」，都是为这两个动词服务的具体机制。

## 模式开关 · 执行 vs 探索（先判在哪个半边，再选武器）

> 框架母本：Sarasvathy「因果逻辑 vs 效果逻辑（Causation vs Effectuation）」、March「利用 vs 探索（Exploitation vs Exploration）」、双轨敏捷（Dual-Track：Discovery ∥ Delivery）。

**这是本方法论最先要判的一步**：你现在是在「把一个已知的果做对」，还是在「发现一个还不知道的果」？两半的纪律**恰好相反**，用错模式 = 用执行的刀去砍探索、或反之。

- **执行模式（本方法论默认·下面法/术的主场）**：果已知、可锁定。逻辑 = **因果**（先定果 → 倒推每一步）。纪律 = 实证先于实操、净效能闸、双重实证、收敛。适用：工程实现、已验证需求的落地、配置/重构、任何「该做什么已定、难在做对」的活。
- **探索模式（果未知、该被发现时切换）**：果不该被预设，而该在行动中涌现。逻辑 = **效果**——不从「固定目标」出发，从「手里有什么」出发，让目标浮现。适用：找 PMF、研究、创作、品牌、任何「连果本身都还不确定」的活。**探索模式的五条纪律（效果逻辑）**：
  ① **手里有鸟**——从你已有的资源（技能 / 认知 / 人脉 / 现有资产）出发，别等完美条件；
  ② **可承受损失**——每个下注先把「输得起多少」封顶，而不是去预测「能赢多少」；封顶了就敢下没有实证支撑的赌；
  ③ **疯狂拼被**——找愿意真上船的伙伴共创，而不是先做完竞品分析；
  ④ **柠檬水**——把意外和不确定当成新机会去用，不当障碍；
  ⑤ **机舱飞行员**——未来不可预测但可塑造，靠影响趋势去控它，而非靠预测去等它。

**关键调和（否则两半的宪法会打架）**：法一的「确定感即红线」是**执行模式的真理、探索模式的毒药**。生成、下注、发明恰恰需要在没有真值时持有 conviction。所以——**探索期允许 conviction，纪律换个抓手**：把「先要真值」换成「**损失封顶 + 每个下注都是可证伪的实验**（造-量-学的学习回路）」。你不需要证据才敢动，但你需要把下行封死、并逼自己从每次下注里读出真信号。

**两模式是极性、不是二选一**：一个项目 / 一个组合往往两条轨并行（March：组织必须同时探索与利用；过度利用 → 陷入 competency trap 吃老本吃到死，过度探索 → 永远收不回投入）。**双轨**：Discovery 轨验「该做什么」（果不定、走探索模式）∥ Delivery 轨「把它做对」（果已定、走执行模式）。**本方法论的法/术是 Delivery 轨的硬核；Discovery 轨走探索模式 + 下面的「需求真值闸」。**

## 道 · 果的资格闸：需求真值（该不该做这个果·先于品级与锁定）

> 这是 Discovery 轨的核心闸——验「值不值得做」。

锁「果」之前先过一道更上游的闸：**这个果凭什么值得做？** 唯一合格的答案——**它来自客户 / 用户的真实痛点，不是自己拍脑袋的自嗨。** 自嗨型项目做得再顶格、再会成长，也是把顶级工艺浇在一个没人要的东西上，是最贵的「为工作而工作」。

- **痛点最易获取方式 = 全网去相关的地方查证**（用户社区 / 评论区 / 竞品差评 / 搜索趋势 / 论坛吐槽 / 现有付费替代品）。本质是把法一的实证纪律用在「需求」上：需求真值同样不能凭「我觉得大家需要」，要去真实数据里读出来。
- **护栏一 · 说的痛 ≠ 真的痛（最深的坑）**：嘴上说要的，和真会掏钱 / 真会改变行为的，常常两码事。**最硬的需求证据不是「有人在抱怨」，而是「有人已经在为这事花钱 / 忍着劣质替代品 / 自己造了 workaround」。** 光有吐槽只是起点信号，不是真值。
- **护栏二 · 嗓门大 ≠ 有代表性**：网上最吵的那批不等于市场。吐槽量 ≠ 市场规模 × 付费意愿；防幸存者偏差（只看见抱怨的人、看不见沉默的不在乎的大多数）与 SEO 伪痛点（有些「痛点」其实是内容营销）。查证要带**源质量判据**（详见法一第二条腿的证据分级）：已付费行为 / 一手 / 权威源 > 论坛热帖 > 随口吐槽。
- **护栏三 · 验的是问题真实，不是你的方案被点名**：真痛点不代表用户点名要你这个解（用户没要过汽车 / 智能手机——最好的产品常服务「用户说不清、但确实在忍」的隐性痛）。闸卡的是「**有人真在为这问题受苦、绕路、花钱**」，不卡「用户是否请求了你的具体解法」。
- **护栏四 · 带证伪去查，不是带结论去找背书**：网上什么结论都能找到证据。别去搜「证明我的点子有需求」，要去搜「证明没人需要它 / 已经被很好解决了 / 用户不会付费」——搜不倒才算过闸（法一·确定感即红线，用在需求上）。
- **护栏五 · 痛点真 ≠ 该你做**：过了真值闸只是「问题成立」，还得叠加「你能做出更好的解 + 够得着这批用户 + 有活路变现 + 没被很好解决」——真值是必要非充分。

> **果层是一条递进：① 资格（需求真值·该不该做）→ ② 品级（顶格 + 自成长·做到什么水准）→ ③ 锁定（果锚·写死并倒推每一步）。** 先证「值得做」，再定「做多好」，最后才「锁死开干」。

## 道 · 果的两个品级要求（果锚不只有「方向」，还有「品级」）

锁「果」的时候，果本身要满足两条品级，否则方向对了、层次却低：

- **品级一 · 对齐行业顶格，不接受「够用」**——任何一步的目标都对齐「该领域实际最顶尖产品的标准」，而不是「能跑就行」。
  **护栏（那对张力 = 顶级 ↔ 时机）**：目标永远顶格；但「彻底做到顶格」只在时机 / 数据成熟时做——时机没到就硬冲顶格 = 过度设计（见术·任务分轻重·二维判断）。**顶格是靶心，不是每一步都要当场射穿。**
- **品级二 · 造「会自我迭代成长的增强体」，不是「一次性解决问题的工具」**——项目的终极果不止于「问题解决了」，而是「一个会持续自我迭代、越用越强的成长体」（数据飞轮 / 反馈回路 / 自改进机制）。
  **护栏**：**架构上从第一天就不把成长回路堵死；成长引擎等时机 / 数据成熟才实例化。** 没数据先造飞轮 = 过度设计。正确节奏 = **早埋种子、到点发芽**：从第一个用户就埋下会成长的钩子，但先把主干跑通，种子到点才启动。

> 这两条属于道 / 果锚层——它们决定「果」长什么样。至于「怎么知道什么才算顶格、什么才是最优」→ 见法一的第二条腿（全网查证当下真值，不凭记忆）。

## 法 · 四条不可豁免的哲学

「法」凌驾一切下层规则，无大小、无场景、无 token 豁免。这是这套方法论的宪法层。（注：法一的「确定感即红线」是**执行模式**宪法；探索模式按「模式开关」里的调和执行。）

### 法一 · 实证先于实操（最深的一条）

做任何事之前，先用真实工具读真实数据、再动手。

**皇冠上的那颗钉子——「确定感本身即红线」：** 心里越是「我就是知道」，越要去验。那种笃定感不是可靠的信号，它常常正是幻觉发作的征兆。

- **实证** = 用工具读真实数据、引用真实原文片段。**不是**「我认为 / 应该是 / 按惯例 / 通常 / 印象中 / 看起来 / 差不多 / 估计是」。
- **红线信号**：上述任一短语在脑中冒头，或**任何关于「当前状态」（工具 / 文件 / 环境 / 数字 / 路径）的陈述句**。纯推理、设计常识、意图判断不在此列。
- **留痕**：每段回复第一行打「证据头」——`【证据】<工具> <路径/参数> → <真实输出片段>`（本段含事实，已实证）/ `【无证据】已查[列出查过哪些地方]均无 → 以下为推测`（找过没找到）。
- **断言任何工具/能力「不可用」前，必先搜一遍**（延迟加载工具：一次没搜出 ≠ 不存在，换词再搜）。
- **改完文件不靠肉眼判损坏，重读回实证**——不凭「成功」二字。**字符级 / 统计类动作走外部工具**（写盘→重读→再数），绝不手打眼数。
- **成本论据**：一次实证约百级 token；一次凭印象出错重做约万级 token。「省 token 跳实证」是伪经济。

**法一的第二条腿 · 实证不止于「现状」，也及于「标准与方法」：**
上面管的是「项目自身现状」的确定感。但还有第二类幻觉更隐蔽——**以为自己知道「最优方法 / 顶级标准 / 最新实践」**。对 AI 尤其致命：训练数据有截止日，「大家现在都怎么做 X」的记忆天然会过期。**过去的知识 = 过期的确定感**，同样是「确定感即红线」，只是验证对象从「我的文件」换成「世界的当下最优」。

- **凡涉「当下最优 / 顶级标准 / 最新版本 / 最佳实践」的判断，全网查证当下真值，不凭训练、记忆、过去。** 要顶级方案，就去查这个领域现在最顶尖的人怎么做，而不是脑补一个「应该是这样」。
- **护栏 A（净效能边界·何时查）**：只在「涉当下最优 / 标准 / 最新版本、且领域在动（工具 / 安全 / 模型 / 价格 / API 都在变）、且错了代价大」时查；不为「1+1」「早成定论的静态知识」去搜。
- **护栏 B（源质量·查到的怎么信）**：*最新 ≠ 最优*（新颖性偏误——查证很容易捞上来「流行」而非「正确」）。按**证据分级**信（借鉴循证医学的证据金字塔）：**已落地一手证据（付费行为 / 可复现结果 / 权威机构 / 原始论文）> 权威二手综述 > 一般报道 > 论坛热帖 / 随口吐槽**。再问一句「谁从这个说法获益」（是不是内容营销 / 软广），把 hype 和 substance 分开。

### 法二 · 以果决行 · 净效能先于动作

这一条是「这步到底服不服务目标」的两个面。（前提：果已知——若果未知，先回「模式开关」走探索模式。）

**以果决行（决策总开关，先于一切触发器）**：① 搞清终极目标（果）——不是这步交什么，是这件事最终要达成的结果；② 多维度分析这个果；③ 先明确、再倒推每一步；④ 每一步都服务于那个果。**红线**：没想清终极的果就动手 = 为过程而过程。

**净效能先于动作（站在法一的事实上）**：动手前问，这步对**当期要务**是正 / 零 / 负（含回滚风险）？**三类当场拦**：无效功（本不该做）/ 负效能（方向反）/ 恶性回滚（改没了已成的）。每个工作单元开头先写死一行「**本单元唯一交付物 = X**」，之后每步问：在交付 X 还是在做别的？做别的 = 停。判不出正贡献 → 不硬干。

### 法三 · 发现问题怎么处理

发现工程债 / 漏洞 / 不一致 → **默认只记一行进待办池，继续主线**。落盘 / dryRun / 读回这套重动作**禁用于「路过的发现」**——除非能说出「不立刻处理会污染主线 / 致错 / 不可逆」之一，否则攒到主线告一段落批量结。**红线**：发现了不记 = 丢债、债复利；但「记住」≠「立刻落盘」，为小发现停下走完整落盘 = 为工作而工作。

**销账闸（与「发现→记」互补·不可豁免）**：任务落盘的**同一个动作**里必须回当期要务源销账——已完成项标死或并入「已闭环存档」，确认待办区只剩真待办。只记不销 = 文档只涨不缩、越长越不可信。**落盘与销账是一个动作的两半，没销账 = 没闭环。**

### 法四 · 留痕即闭环 · 大脑常生长

任务闭环后，把教训**生进核心规则文件**，不记成流水账。**三类记录**：① 决策与结论 = 长期留；② 可复用的坑 = 归一处长期留、定期审；③ 一次性过程 = 标到期、到点删。**膨胀的解药是「出」的机制（到期淘汰），不是「少记」。** 这是「大脑生长而不臃肿」的唯一秘诀。

## 术 · 怎么落地

### 术一 · 五触发器（每个任务强制走·缺一即跑偏）

① **观象**：出方案前一句话判时位——这步在什么阶段、该潜还是该飞、服务终极果哪一条？都不是 = 停。② **守常**：动手前读项目准则文件 + 使命源 + 红线。③ **执中**：决策显式说出那对张力、中点为何取此（机制版见「术·张力管理」）。④ **不止**：闭环后教训生进核心。⑤ **留痕**：每段回复第一行打证据头。

### 术 · 张力管理（把「执中」从姿态升级成机制）

> 框架母本：Barry Johnson「极性管理（Polarity Management）」、Smith & Lewis「Both/And Thinking」。

「执中」原来只要求你**说出**那对张力，但**说出 ≠ 解决**。机制在这里：

- **先分类**：这是「要解的问题」（either/or，选一端就对）还是「要管的极性」（both/and——两端互依、任一端单独都不可持续）？大多数核心矛盾是后者。
- **别找死中点，管极性**：目标是**取两端的上side、避「过度偏一端」的下side**。极性会像无穷循环那样自然流动（偏久了某一极必现其下side，产生回摆压力）。
- **机制 = 早期预警信号 + 自我校正**：给每对张力设一个「我偏到某极下side 了」的**可观察信号**，一触发就往另一极上side 校正。

三对核心张力的**可操作取中问法**（附预警信号）：

| 张力 | 取中问法 | 偏一极的预警信号 |
|---|---|---|
| 实证 vs 成本 | 「错了要重来多少？**重来成本 > 验证成本 → 验**」 | 过度验：在验错了也便宜/可逆的东西 ｜ 验不足：在凭记忆断言当前状态 |
| 顶格 vs 时机 | 「这块的顶格**现在有数据/前置支撑吗**？没有 → 埋钩子、先跑通、标记待升」 | 过度顶格：用户还没有就在镀金 ｜ 过度将就：核心命脉也只做「够用」 |
| 记一行 vs 立刻修 | 「**顺路（同文件/同上下文）且 < N 分钟 → 修；否则记**」 | 过度修：主线反复被小发现打断 ｜ 过度攒：待办池只涨不清、债滚债 |

### 术 · 任务分轻重（含「方法论熔断」）

- **重动作**（碰核心文件 / 不可逆：落盘 / 部署 / 删改 / 外发 / scp）→ 六步 SOP：① 明确任务 + 净效能 → ② 实证盘点 → ③ 大局观找最优 → ④ 施工图 + 人拍板 → ⑤ 逐步落实（每段 ≤15 行、段后双重实证）→ ⑥ 自检三问 + 返工。
- **轻动作**（改一行 / 查一值 / 答一点）→ 净效能一句 + 证据头 + 做完双重实证。
- **重轻由客观属性定，不由「觉得轻」定；拿不准按重走。任何档位，净效能 + 证据头都不可省。**

**熔断（方法论对自己的过度设计免疫·不可省）**：**这套方法论本身也可能是过度设计**——它违反了自己的二维判断，如果不设熔断的话。判据：
- **可逆 + 短周期（一次性 / 数小时）+ 低 stakes** → 整套文档架构 / 开窗协议 / 销账闸 = 纯仪式，**只跑「降级内核」**（见下节），别为一个两小时脚本套六件套。
- **全套（文档地图 + 开窗协议 + 四方协同 + 销账）只在「高 stakes ∪ 不可逆 ∪ 长周期 ∪ 多窗断续」时上。**
- 一句话：**用重方法的成本 > 出错的成本时，重方法本身就是负效能。**

### 术 · 多 P0 排序（都该做时，怎么定先后）

> 框架母本：WSJF = 延迟成本 ÷ 工作量（Reinertsen「CD3」→ SAFe）、RICE = 覆盖 × 影响 × 信心 ÷ 工作量、预承诺 kill 标准（对抗沉没成本）。

「向果」只回答「**这个该不该做**」（off-strategy 的砍掉），但当**十件事都 on-strategy、都该做**时它哑了。补一个排序机制：

- **按「价值/工作量」比排序，不按「谁喊得响」排。** 两个常用算子：**WSJF = 延迟成本 ÷ 工作量**（延迟成本 = 业务价值 + 时间紧迫度 + 风险消减/机会开启）；或 **RICE = 覆盖 × 影响 × 信心 ÷ 工作量**。都把「主观吵架」变成「可复现算分」。
- **反直觉但关键**：直接价值低、但**时间紧迫（硬截止/罚款）或风险高**的事，可能要排在价值更高的事**前面**（例：合规项先发，哪怕它不「性感」）。别只看 raw 价值。
- **尊重依赖拓扑**：被别的事卡着的、或卡着别的事的，按依赖图调序，不只按分数。
- **预承诺 kill 标准（对抗沉没成本）**：开工前就写死「满足什么条件就停这件事」——决策**只看未来价值，不看已投入多少**。没有预设的 kill 线，沉没成本会让你在死项目上一直加注。

### 术 · 执行边界（可逆性决策）

> 框架母本：Bezos「双向门 vs 单向门（Type-2 / Type-1 决策）」。

可逆可判的自主做 / 判不出先最小可逆探 / 定方向·不可逆的才问人 / 问不到人就把可逆的做完、不可逆的留着等拍板。**双向门（可逆）快走、单向门（不可逆）慢走且要人拍板。** 这是人 + AI 的自主权契约。（注意：人际动作大多是「半可逆灰区」，此二分映不进去——见「方法论的边界」。）

### 术 · 大任务四方协同闭环

有一定复杂度、需落地执行的任务（架构升级 / 功能开发 / 配置变更 / 批量重构）→ **走四方闭环，不要 AI 一个人从头干到尾、也不要跳过实证直接写代码**。六步：① 充分沟通出共识 → ② 充分实证出铁证（无实证不出图）→ ③ AI 出施工图（唯一权威蓝图，真值集中列、**禁手打**）→ ④ 落地执行者据工单落地（dryRun + 硬读回自验，不碰真机）→ ⑤ AI 检验（对照施工图逐项查，不妥则回炉）→ ⑥ 人 + AI 真机测评，过则按销账闸归档。
**分工**：人掌舵拍板 + 执行不可逆动作 / AI 实证·设计·把关 / 执行者规模化落地。**红线**：跳过实证直接出图 = 违最高铁律；施工图真值靠手打 = 穿帮源；执行者成果不检验直接上真机 = 漏洞带进生产。**判据**：这任务值不值得画一张施工图？（另注·康威定律：你的团队/协作结构会渗进产物架构——多方分工怎么切，产物就长成什么样，故分工和架构要一起设计。）

### 术 · 双重实证 + 证据头

**双重实证**：动作前的证据 + 动作后的读回，永不信「成功」二字，落盘后读回字节数 / 行数 / MD5 / 关键词。**证据头**：把「留痕」落成每段回复第一行的硬约束。

## 反模式清单 · 实战踩出来的坑（首要防·比正面规则更该背）

1. **滞后快照陷阱**——凭一份过期的索引推断出某「问题」，再一头扎进真机一行行验证它，把人拖进多轮手动贴输出。**答案常在最近的对话里。** 防：刨真机前先搜历史对话对齐现状；索引是滞后路由快照，非当前真值源。
2. **为工作而工作**——为路过的小发现走完整落盘；没想清终极的果就动手。防：以果决行 + 净效能闸 + 法三「只记一行」。
3. **省 token 跳实证**——一次实证约百级 token，一次凭印象出错重做约万级。防：法一，无 token 豁免。
4. **凭名字 / tag 判孤儿**——运行时系统里因为「名字看起来没人用」就删它，没双向追它连着谁。防：追全链两端；不确定默认保留；运行时误删可能没后路。
5. **手打真值**——数字 / 路径 / 哈希凭记忆敲进施工图 = 穿帮源。防：真值工具读出来粘贴，字符重的编辑走外部工具 + 重读。
6. **只记不销**——记了完成项却不在真值源销账 → 文档只涨、越涨越不可信。防：销账闸——落盘与销账是一个动作。
7. **凭「成功」二字信落盘**——工具报成功但根本没落 / 落坏了。防：双重实证，永远读回。
8. **整读大文件开窗**——每开一窗把整个大进度文件从头读一遍，烧光上下文。防：开窗只硬读两份小文件（规则卡 + 索引顶部），靠指针路由 → 只 head/tail 取相关段。
9. **忽视文件编辑的原子回滚**——一处锚点不匹配就静默回滚整批。防：先 dryRun；用最短唯一 ASCII 锚点，避开会被悄悄改坏的生僻字。
10. **假实证 / 仪式化证据头（Goodhart 陷阱）**——贴了 `【证据】` 但**验错了对象、验得很浅**，形式合规、实质落空，制造**比没验更危险的假信心**。母本：Goodhart 定律「一个指标一旦变成目标，就不再是好指标」——证据头一旦沦为打卡，就被 game 了。防：验之前问「我验的是不是**正确的对象**、深度**够不够**」；证据头的职责是纪律，不是勾选框。

## 方法论的边界 · 它不管什么（诚实划界，胜过假装覆盖）

> 框架母本：康威定律 / 团队拓扑（Skelton & Pais）、Brooks 定律、Dunbar 数 / 认知负荷。

**这是一套「造物」方法论（管文件 / 代码 / 系统），不是「带人 / 造局」方法论。** 它默认一个高自律的单人或极小高信任团队。以下维度它**不覆盖**，团队 > 约 5–9 人 / 强人际项目需**另配**一套协作 / 组织方法论：

- **组织与沟通**：委员会决策、并行工作流互踩、跨时区交接、组织政治、动力 / 倦怠 / 长期可持续——本方法论一个字没有。
- **可逆性映不进人际**：一次难谈的话不能 dryRun，一次得罪人很少能干净回滚；人的动作大多是**半可逆灰区**，而执行边界是二分的。硬套会误判。

即便如此，有几条**能反向补人的维度**，值得带走：
- **康威定律**：系统结构 = 组织沟通结构的复制。**团队怎么切，产物就长成什么样** → 团队和架构一起设计（甚至反向：先设计团队去逼出想要的架构）。
- **加人不是线性提速（Brooks 定律）**：给已经晚的项目加人会更晚（沟通成本 O(n²)）。宁可**缩小范围 / 限认知负荷**，也别无脑加人——「软件按团队来定规模，不是团队按软件来定」。
- **bus factor 保险**：本方法论的「大脑在文件里」文档架构，恰好是 bus-factor 保险——**创始人不在，知识还在盘上**。这是它给「人」维度的一个免费副产品。

## 优雅降级内核 · 资源/纪律不足时，什么绝不能省

**半吊子地跑全套 = 假严谨，比没纪律更糟**（形式在、实质空，还骗自己「我很规范」）。当你没条件跑全套时，**别硬撑全套仪式，退到这个不可再降的内核，诚实地跑**：

1. **需求真值**——别建自嗨（哪怕只做一次轻量查证，也别凭「我觉得有人要」）。
2. **实证现状不凭记忆**——法一的核。关于当前状态的每一句，先读再说。
3. **不可逆动作前停手问人**——执行边界的核。可逆的放手做，单向门必停。

**这三条在任何档位、任何模式、任何资源水平下都不豁免。** 其余（文档地图 / 开窗协议 / 四方协同 / 销账闸 / 排序算子）都是可按 stakes 伸缩的外层。

## 元铁律 · 压缩内核（一页速查）

- **模式开关**：先判在「执行」（果已知·因果·实证收敛）还是「探索」（果未知·效果·封顶损失下注 + 学习回路）半边——用错模式 = 用错刀。
- **需求真值闸**：果必来自客户 / 用户真实痛点（全网查证），非自嗨。验「问题真实（有人在为它花钱/绕路/造 workaround）」非「用户点名要你的方案」；带证伪去查，嗓门大 ≠ 有代表性。
- **果锚**：**先过资格（需求真值）→ 再定品级（顶格 + 自成长）→ 才锁定终极的果并倒推每一步**。
- **元铁律 0**：实证先于一切。断言工具「不可用」前必先搜。无实证不开口、不出图。
- **查证最新 + 源质量**：涉「最优 / 顶级标准 / 最新」全网查当下真值；最新 ≠ 最优，按证据分级信（付费行为/一手/权威 > 综述 > 报道 > 论坛帖）。
- **元铁律 0.5**：发现问题不丢债——记下来；便宜且顺路就当场修，否则批量结。
- **净效能闸**：这步对当期要务是正 / 零 / 负？拦无效功 / 负效能 / 恶性回滚。
- **张力管理**：核心矛盾多是「要管的极性」非「要解的问题」——取两端上side、设预警信号防偏一极、自我校正。
- **排序机制**：多个都该做时，按 WSJF（延迟成本÷工作量）/ RICE 算分排，紧迫/高风险可越过高价值；预设 kill 线防沉没成本。
- **执行边界**：可逆（双向门）自主做；判不出 → 最小可逆探；不可逆（单向门）→ 问人。
- **双重实证**：动作前 + 动作后都验，永不信「成功」。
- **销账闸**：落盘即销账，一个动作两半。
- **留痕即生长**：教训生进规则，到期淘汰。
- **四方协同**：复杂任务 → 沟通 / 实证 / 施工图 / 落地 / 检验 / 真机测评；AI 推进到不可逆动作前停手等按扳机。
- **方法论熔断**：可逆 + 短 + 低 stakes → 整套是过度设计，只跑「降级内核」三条。
- **降级内核（永不豁免）**：① 需求真值 ② 实证不凭记忆 ③ 不可逆前停手。

## 移植指南 · 如何在新项目上实例化这套方法

方法论本身是**不变量**；下面几样是每个项目要各自填的**变量**。

1. **果锚（North-Star）**——**写果锚之前先过「需求真值闸」**：全网查证这个果来自真实痛点（不是自嗨），且拿「已付费 / 绕路 / 造 workaround」级证据、不是光有吐槽。过闸后，在路由文件顶端用一段话写死终极结果，永不滚动。定义它的「几条腿 / 几条主线」（每个动作都必须服务的 2–3 个子目标）。**果锚还要写清两条品级**：① 对齐行业顶格、不接受够用；② 造会自成长的增强体、非一次性工具（架构不堵死回路，引擎到点才实例化）。
2. **红线集**——本项目领域专属的「绝不做」清单。**把每条红线贴在它所守的规则旁边，不做成独立清单**（读到规则即见其红线）。
3. **权威源文档地图**——按「性质闸」分家（写入前问：**是地址还是内容？当下还是历史？**）：规则卡（每窗必读，只装规则）/ 展开手册（细则，用到再翻）/ 当前态指针（路由索引 + P0）/ 死档（历史，开窗不主动读）。每份文档只回答一类问题；守住性质闸，文档自然恒容。
4. **工具怪癖登记表**——本项目工具链的具体坑（原子回滚、shell 语法差异、写工具落到哪个文件系统、某搜索对某类文件不可靠……）。每条都是从一次真实翻车提炼的规则。
5. **开窗协议**——给每个「失忆重启」的 AI 新窗做的 fail-stop 铁闸：**开口前先验工具 + 读规则卡 + 读当前 P0**。把具体读哪几份对齐到本项目文档地图。
6. **协作分工契约**——谁执行不可逆动作、谁设计 + 把关、谁规模化落地。**AI 备好命令、推进到不可逆动作前停手等拍板。**
7. **模式与边界声明（V1.3 新增）**——开项目前先声明三件事：① 这项目现在在**执行**还是**探索**模式（决定用哪套纪律）；② 会不会牵涉 **> 5 人团队 / 强人际**（是 → 另配组织方法论，本方法论只管造物那半）；③ 你的**降级内核**是哪三条（资源紧时退到这里，不硬撑全套）。

> **分层提醒（不可省的自省）**：本方法论里，哪些是**永恒原则**、哪些是**当代 AI 的补偿件**，要分清——
> - **永恒**：需求真值、实证先于实操、以果决行、净效能、张力管理、闭环+生长。这些跟 AI 强弱无关。
> - **当代 AI 补偿件**：fail-stop 开窗协议、记忆/文档架构、强制证据头——它们存在，是因为**这一代 AI 会失忆、会幻觉**。AI 一变（持久记忆、更好校准），这些要**重新审视、可能过时甚至反效果**。
> - 这正是法一第二条腿（查证最新、别用过期假设）用在方法论**自己身上**：别把 2026 年的 AI 假设焊成永恒真理。动手删任何一条补偿件前，先搞清它**当初为什么在**（Chesterton 栅栏：没搞懂为什么立的栅栏，别拆）。

---

> **一句话记住这套方法：**
> **先判半边**（执行 or 探索）；执行半边——用**需求真值**证该做、用**果锚**（顶格 + 自成长）定方向、用**实证**踩每一步、用**净效能 + 排序**挡跑偏定先后、用**张力管理**在矛盾里取中、用**可逆性**划人机边界、用**四方闭环**上规模、用**销账 + 淘汰**让大脑生长而不臃肿；资源不足就退到**降级内核三条**，绝不半吊子硬撑——**事事有终，生生不息。**
