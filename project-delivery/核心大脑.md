# 核心大脑 · v1.0

> **定位**：整个项目交付法的**中枢**。四个阶段是它做的事，**它是做事的那个器官**。
> 终极目标是「去哪」，道法术器是「怎么想」，**核心大脑是「现在做什么、谁做、做到什么程度停」**。
> 配套：《项目交付法》。本文件是唯一真源，版本写在文件内。
> 立于 2026-07-28。源出 NEXUS HaaS「协同大脑」实战原型 + Savant-Learn 的判定侧教训。

---

## 0 · 为什么必须有这个器官

没有它，四个阶段会以**看起来完全正常**的方式失效：

| 缺哪个器官 | 实测到的失效形态 |
|---|---|
| 缺**状态** | 总图记着「某层 14/17 未完成」，实读代码是 17/17 全完成——**在过期的图上找位置，找到的是错的位置** |
| 缺**排产** | 五个批次全投在已经够用的那一环上，而三条空链路一行代码没有——**在非约束处优化，产出一点不涨** |
| 缺**监察** | 收口判据写成过程量，于是循环**在结构上关不掉**，六个周期问的是同一个问题 |
| 缺**记忆** | 每次重新解释一遍背景；债只记不销，文档只涨不缩 |
| 缺**法典** | 规则散在各处，或膨胀到没人读——**等于没有** |

**这五样不是文档，是器官。** 文档会过期，器官要一直在跑。

## 1 · 六个器官

| # | 器官 | 一句话职能 | 形态要求 | 失守后果 |
|---|---|---|---|---|
| ① | **法典** | 每个动作都要在脑子里过一遍的规则 | 一张卡，**带性质闸**，薄 | 膨胀 → 没人读 → 等于没有 |
| ② | **状态** | 现在到哪了（真值） | **机器生成，人不手写** | 过期的图 |
| ③ | **排产** | 下一步做什么、做到什么程度停 | 一注一张，带胃口与完工判据 | 在非约束处使劲 |
| ④ | **监察** | 有没有跑偏 | **可机械计算的几个数** | 循环关不掉 |
| ⑤ | **记忆** | 跨窗、跨人、跨实例的连续 | 交接三件套 + 销账闸 + 淘汰机制 | 每次重来 / 债复利 |
| ⑥ | **进化** | 越做越强且不倒退 | **三层可改性 + 四环 + 生灭同设计** | 只会变，不会长；或改了尺子让指标好看 |

> ①–⑤ 让项目**做得成**，⑥ 让它**越做越强**。**缺⑥ = 一次性工程，不是活的智能体。**

## 2 · 器官① · 法典（规则内核）

### 性质闸（**决定这张卡会不会烂掉的唯一机制**）

> 本卡只装「**每个动作都要在脑子里过一遍**」的规则。
> 冲以下三类即移出：① 解释「为何这么定」 ② 某场景的操作细则 ③ 历史 / 案例。
> 移到展开手册或状态文件，卡里只留规则本身。
>
> ⭐ **不按字数管控——字数是症状，性质才是病根。**

### 两条结构律

- **锢不在脑子里，在文件里。** 动手前读文件，不凭记忆。
- **启动器只指向，不复制。** 注入层（全局指令 / 项目指令）只写「去读哪张卡」，**绝不抄内容**——抄一份就是两份，两份必然分叉。

### 内容边界

法典里放：三条永不豁免、五触发器、轻重分级、执行边界、表达要求、各条旁边的红线。
法典里**不放**：为什么这么定、某个工具怎么用、上次踩了什么坑。

## 3 · 器官② · 状态（现在到哪了）

### 铁律：状态部分**由机器生成，人一个数字都不许手写**

这是本器官与 NEXUS 原型相比**唯一的实质升级**，来自 Savant-Learn 的实测：
人工维护的完成度表，写完当天就过期了，而没有任何一处会报错。

**做法**：写一个状态生成器，每次从**真源本身**读出来：
- 原理层：从代码常量读根数、各栏是否齐
- 法层：数文件
- 术层：数判据函数、数链路是否存在
- 产物：数落盘件、数通过件
- 指标：读真实测量结果

**配一条对账回归**：文档里的数字与生成器输出不一致 → 红。

### 防滞后快照陷阱（**NEXUS 用血换的，原样保留**）

任何人工维护的状态文件都是**滞后快照 + 路由索引，不是当前真值源**。

答「现在到哪 / 某事解没解 / 某物做没做」之前：
1. 先对齐最近的实际记录（最近几次对话 / 最近的落盘）
2. 再用索引导航
3. 真值以**最近记述 + 真实环境实证**为准

> ⛔ **禁止凭滞后快照推断出一个「问题」，然后一头扎进真实环境一行行刨去验证它。**
> 答案常常就在最近的记录里。刨之前先查记录。
> 凭滞后快照刨伪命题、把人拖进多轮手动贴输出 = 负效能。

### 单一权威源

每一类关键数字/口径指定唯一权威源文件；其他文件只能写「见 X §N」，**不许自己抄一个数**。
冲突时以权威源为准，下游不逐行改，**插废弃戳指向权威源**。

**⭐ 锁机制，不锁数字**：结构/责任链/周期口径锁死；具体数字在没有真实反馈前**故意留空**。
⛔ **任何人（含 AI）不得凭印象填一个数进去当定数。**

## 4 · 器官③ · 排产（下一步做什么）

### 排产的输入只有三样

**果**（终极指标）+ **约束**（唯一那个瓶颈）+ **状态**（现在到哪）。
三样缺一，排产就是拍脑袋。

### 排产四问（每一注开工前，缺一不开工）

1. **服务哪个终极指标？** —— 说不出 → 不开工
2. **属道法术器哪一层？** —— 越级的打回
3. **胃口多少？**（愿意花的时间/钱上限）—— 先定胃口再定范围，不是先估时
4. **完工判据是什么？** —— 一句能被判为真/假的话，**且不能是过程量**

### 排产红线

- ⛔ **在非约束处优化 = 无效功。** 自查：「这一环再好十倍，终极指标会动吗？」不会 → 它不是约束。
- ⛔ **排产判断必须放在花钱之前。** 能零成本算出来的可行性，不许让每一注烧一轮预算去发现。
- ⛔ **本单元唯一交付物写死在开头**，之后每一步问：这步在交付它，还是在做别的？做别的 = 停。

### 净效能闸（动手前，**站在实证事实上**）

问：这步对当期唯一交付物是**正 / 零 / 负**（含回滚风险）？

**三类当场拦**：无效功（本不该做）/ 负效能（方向反）/ 恶性回滚（改没了已成的）。

判不出 → 不硬干：**能判的自主做 / 判不出先做最小可逆探 / 定方向·不可逆的才问人 / 问不到人就把可逆的做完、不可逆的留着等拍板。**

### 熔断

到期没做完 → **默认作废，不默认延期**。要继续必须重新下注。
**一注最多续一次，且续之前必须重写完工判据。** 第三次下注 = 强制回阶段一/二重审。

## 5 · 器官④ · 监察（有没有跑偏）

### 5.1 物理形态约束 > 软指令（**这条是整个大脑最重要的工程原理**）

软指令（「记得先实证」「注意别跑偏」）在状态好时有效，**状态差时正好失效——而状态差时正是最需要它的时候**。

**解法：把它变成一个缺失即可见的物理形态。**

| 软指令（会失效） | 物理形态（缺了一眼就看出来） |
|---|---|
| 「动手前先实证」 | **每段回复第一行必须是证据头**：`【证据】<工具> <路径/参数> → <真实输出片段>` 或 `【无证据】已查[列出查过哪些地方]均无 → 以下为推测` |
| 「开窗要先盘点环境」 | **开窗硬证据**：粘贴一两个**有确定真值、编造即穿帮**的原始返回（如工具查询的原始计数、可写目录的原始路径行）。**填不出 = 没执行开窗动作 = 本窗作废重开。** |
| 「别凭印象说工具不可用」 | **断言任何工具「不可用」之前必先查工具清单**；开场第一个动作若不是查清单却说「没有 X」= 当场抓获 |

> 三次迭代证明：关口式软指令可以忘打，**段首格式忘不掉——因为它是格式错，一眼可见。**

### 5.2 可机械计算的健康指标（每周期算一次）

| 指标 | 怎么算 | 警报条件 |
|---|---|---|
| **判据 vs 法** | 法涨了几格、判据涨了几条 | **判据涨得更快 = 正在用打补丁代替写法** |
| **文档增量** | 状态文件本周期涨了多少 | 只涨不缩 = 只记不销 |
| **待办年龄** | 最老的一条挂了多久 | 长期不动 = 要么该做要么该删 |
| **终极指标可测数** | 三到五个指标里有几个测出过真数 | **0 = 果是空的，一切读数都无参照** |

### 5.3 量具自检（判定工具在出第一个读数之前）

重复性（量两遍一样吗）/ 再现性（换个人换台仪器一样吗）/ **分辨力（能分成几档）**。
**能分档数 <3 基本只是个通过/不通过的开关，<2 完全无用。**
⚠ 只做重复性最骗人：它只证明仪器不抖，不证明仪器对准了东西。

### 5.4 五触发器（每个任务强制走，缺一即跑偏）

| # | 触发器 | 做什么 |
|---|---|---|
| ① | **观象** | 出方案前一句话判两问：**时位**（这步在什么阶段、该潜还是该飞）+ **向果**（服务终极目标哪一条）。**两者都不是 → 停，这步可能在偏。** |
| ② | **守常** | 动手前读法典 + 使命源 + 红线 |
| ③ | **执中** | 决策显式说出：这件事的那对张力是什么、中点为何取此 |
| ④ | **不止** | 闭环后把教训**生进核心规则**，不记成流水账 |
| ⑤ | **留痕** | 每段第一行打证据头 |

## 6 · 器官⑤ · 记忆（跨窗、跨人、跨实例的连续）

### 6.1 交接三件套

**方法底座**（法典）+ **项目准则**（这个项目的地图/路由/红线）+ **当前状态与下一步**。

⚠ **交接的是方法的连续，不是某个实例的人格。**
把一切沉淀成可迁移的文件 → 不押注单一供应商、单一实例、单一模型。

### 6.2 销账闸（**与「发现→记一行」互补，不可豁免**）

> **落盘与销账是一个动作的两半。没销账 = 没闭环。**

任务落盘的**同一个动作**里必须回到状态源销账：已完成项标死或并入已闭环区，确认待办区**只剩真待办**。

**只记不销 = 文档只涨不缩、越长越不可信。**

### 6.3 下沉判据（**触发是「彻底办好」，不是「攒厚了」**）

字数是症状，**事的状态才是病根**。彻底办好 = 三条全中：
1. 真实环境实证过（不是设计完、不是大概通）
2. 无残留子待办（带出的小债已各自归位）
3. 不再依赖任何未决前提（不是「等 X 好再说」）

三条全中 → 下沉归档，状态源只留指针。**缺一条 = 它还是活的，留在待办区。**

### 6.4 记录三类 + 淘汰

**A 决策与结论** → 长期留 · **B 可复用的坑** → 归到一处长期留、定期审 · **C 一次性过程** → 标到期、到点删。

淘汰判据一句话：**这条，未来任何一次还会去读吗？** 不会 → 删（不是下沉，直接删）。

**膨胀的解药是「出」的机制，不是「少记」。** 到点主动删，谁路过谁删。
⚠ 归档前先确认归档目标**仍在版本控制与回归的视野内**——否则「归档」只是挪到没人看得见的地方。

## 7 · 器官⑥ · 进化（**让方法与项目都成为活的智能体**）

> 前五个器官让项目**做得成**。这一个器官让它**越做越强，且不倒退**。
> 它同时管两级：**方法自己的进化**（跨项目）与**每个项目自己的进化**（项目内）。
> 两级用同一套机器。

### 6.5.0 前提：活 ≠ 全部都活。**死核 + 活壳。**

⚠ **这是设计一个活系统时最容易搞错的地方。**

一个所有部分都可变的系统不是「更活」，是**没有基准**——它会朝着「更容易达标」的方向漂，
而不是朝着「更好」的方向长。生物也一样：基因组极端保守、修复机制极端严格，
**正因为核是死的，免疫系统和神经元才敢是活的。**

> **核必须死，壳才能活。**

### 6.5.1 三层可改性（**分层判据是可证伪的，不靠品味**）

| 层 | 装什么 | 谁能改 | 归属判据 |
|---|---|---|---|
| **宪法层** | 果的定义 / 「好」的判据 / 红线 / 回滚阈值 / 三条永不豁免 | **仅人，且必须留痕** | ⭐ **一个规则若「违反它能让指标变好」，它就必须锁死在这一层** |
| **演化层** | 参数 / 权重 / 模板 / 判据措辞 / 排产策略 / 提示词 | **系统全自动** | 改错了能被指标发现并自动回滚 |
| **提案层** | 对宪法的质疑 / 新原理提名 / 新证据 | **系统只写不执行** | 触及宪法的一切 |

**那条归属判据是这套设计的地基。** 它把「什么该锁死」从一个偏好问题变成一个可验证的问题：
拿任意一条规则问「违反它，短期指标会变好吗？」——会 → 它必须锁死，否则系统迟早会去违反它。

### 6.5.2 进化的四个环（缺一即不是活的，只是会变）

```
① 感知 —— 拿到真实结果信号（不是自评）
② 变异 —— 产生候选改动
③ 选择 —— 用一个【系统不能自改的】判据留或弃
④ 保留 —— 改动落进真源，带留痕与版本
```

⛔⛔ **最危险的失败形态不是指标下跌，是「系统改了尺子让指标看起来没跌」。**
把答案塞进提示、把考试改开卷、把支架永久不消褪——每一样都能让短期指标上升。
**所以第③环的判据必须在宪法层，且系统不能碰。**

⛔ **无外部信号的自我奖励闭环 = 必然的指标劫持。** 感知环取不到外部信号时，
**整个进化环是死的**——此时系统只能记录、提案，不许自动执行改动。

### 6.5.3 生与灭必须同时设计（**只增不减的活系统死于自重**）

我们已经实测过三次膨胀：坑库涨到上千行、诊断脚本上百个、闸只增不减。

> **每条新规则入库时，必须同时写两件事：它防的是什么 + 它的失效判据。**

**三种可删信号（机械可测，每周期扫一次）**：

| 信号 | 含义 | 处置 |
|---|---|---|
| **从未触发过** | 它防的事没发生过，**或者它根本没接上** | 先查第二种可能（「写了≠在起作用」四问），排除后删 |
| **触发后总是被绕过** | 它写错了层 | 回上层补，删掉这条 |
| **它防的事已被结构性消除** | 被更上层吸收了 | 删，留一行索引 |

**膨胀的解药是「出」的机制，不是「少记」。**

### 6.5.4 方法自己的进化信号（**只有一种最值钱**）

方法的果 = **用它做出来的项目成了没有**。

而方法的错误信号，最值钱的只有一句：

> **「按方法做了，还是撞了。」**

那是**方法的缺口**，不是执行的失误。每次出现必须记四件事：
撞在哪一关 / 方法哪一条本该拦住它 / 为什么没拦住 / 补哪一层。

⚠ 反过来也要记：**哪一条规则真的拦住了一次事故**。
没有这条记录，删除判据里的「从未触发过」就没有真值可查。

### 6.5.5 防局部最优：三个变异源，缺一即近亲繁殖

| 源 | 说明 | 状态 |
|---|---|---|
| ① **内部实战** | 自己撞出来的 | 一直有 |
| ② **跨项目** | 另一个项目撞出来的 | ⭐ 已运行一次：NEXUS 的协作与组织沉淀 × Savant 的判定侧纪律，两边互补，各自单独都不完整 |
| ③ **外部** | 世界一流的公开方法 / 新文献 | 需主动去取，不会自己来 |

**只有①会收敛到局部最优**——一个只从自己错误里学习的系统，最终只擅长不犯自己犯过的错。

### 6.5.6 核与适配层（防 N 个方言）

方法本身也走道法术器：

| 层 | 方法的对应物 |
|---|---|
| 方法的**道** | 三条永不豁免 + 三层可改性 + 四环 —— **通用核，唯一真源，版本化** |
| 方法的**法** | 每类项目的适配（软件 / 硬件 / 内容 / 合规…） |
| 方法的**术** | 关口清单、状态生成器、健康指标 |
| 方法的**器** | 模板、脚本 |

**项目可以有自己的适配层，但对核的改动必须回流到核。** 否则 N 个项目跑出 N 个不兼容的方言，
跨项目变异源（第②个）就断了。

### 6.5.7 自应用 —— 好方法的唯一检验

> **本方法必须能用它自己造出来。造不出来，说明它错了。**

拿它量它自己：

| 关口 | 本方法当前状态 |
|---|---|
| 有果吗 | 有：用它做的项目成了没有 |
| 果可测吗 | ⚠ **弱**。目前只有 n=2 个项目 |
| 有量具吗 | ⚠ 健康指标有几条可算，但**分辨力没做过检查** |
| 有终止条件吗 | 有：每条规则带失效判据 |
| 有外部确认吗 | ⚠ **没有**。还没有第三方用它做成过项目 |

⭐ **老实的自我定级**：按本方法自己的规则——**观察 1 次是现象，≥3 个独立实证才升级为铁律**——
本方法目前建立在 **2 个项目**上。**它现在是 v2.0 的工作草案，不是铁律。**
第三个项目跑完之前，用它，但别把它当成已验证的东西。

### 6.5.8 每个项目怎么做成活的

同一套机器，项目层多一条**硬前提**：

> **果必须能被真实用户数据测到。测不到 → 进化环第①步（感知）是断的 → 整个环是死的。**
> 此时项目不是「活的智能体」，只是「会变的系统」。两者的区别是有没有外部真值在选择。

项目层落地：三层可改性划清 → 感知接上真实数据 → 变异只许在演化层 → 选择判据锁在宪法层 → 保留必带版本与留痕。

### 6.5.9 进化红线

- ⛔ 系统不得修改自己的评判标准
- ⛔ 不得为了指标好看而改口径（改口径必须走提案层，由人裁决）
- ⛔ 感知环取不到外部信号时，不许自动执行改动（只许记录与提案）
- ⛔ 只增不减
- ⛔ 改动无留痕（改了什么 / 因为哪次实测，缺一不许改）
- ⛔ 把「运气」读成「疗效」：一次好转不是证据，看分布与重复

## 8 · 大脑怎么跑起来（落地形态）

一个项目的核心大脑 = **五个文件 + 一个生成器 + 一个注入点**：

| 器官 | 落地物 | 谁维护 |
|---|---|---|
| ① 法典 | `法典.md`（薄，带性质闸） | 仅创始人 |
| ② 状态 | `状态.md` —— **由 `状态生成器` 产出，人不手写** | 机器 |
| ② 状态·权威源 | `权威口径.md`（关键数字唯一真源） | 仅创始人 |
| ③ 排产 | `在建.md`（一注一张：指标/层/胃口/完工判据） | 大脑窗 |
| ④ 监察 | 生成器里的健康指标段 + 各处物理形态约束 | 机器 |
| ⑤ 记忆 | `待办池.md`（A/B/C 分类）+ `交接.md` | 大脑窗 |
| ⑥ 进化 | `宪法.md`（锁死·仅人改）+ `提案层.md`（只写不执行）+ 规则台账（每条带「防什么 / 失效判据 / 触发过几次」） | 宪法仅人 / 台账机器 |
| 注入点 | 全局/项目指令 —— **只写「去读法典」，不抄内容** | 仅创始人 |

**每次开窗的固定动作**：
```
0. 打开窗硬证据（原始返回，编造即穿帮）
1. 读法典（守常）
2. 跑状态生成器 → 拿真值（不读人写的完成度）
3. 对齐最近记录（防滞后快照）
4. 读在建.md → 知道这一注是什么、判据是什么
5. 观象一句话（时位 + 向果）→ 才动手
```

**每次收窗的固定动作**：
```
1. 销账（回状态源标死已完成项）
2. 教训生进法典（不记成流水账）
3. C 类过程标到期
4. 更新在建.md / 交接.md
```

## 9 · 这个大脑自己的红线

- ⛔ **法典膨胀** → 性质闸失守。定期按三类清洗，不按字数管。
- ⛔ **状态由人手写** → 必然过期，且不会报错。
- ⛔ **注入层抄内容** → 两份必然分叉。
- ⛔ **软指令代替物理形态** → 状态差时正好失效。
- ⛔ **排产不看约束** → 在非约束处使劲，产出不涨。
- ⛔ **只记不销** → 文档只涨不缩、越长越不可信。
- ⛔ **拿滞后快照当真值** → 刨伪命题，负效能。

> **法典让每个动作有规矩，状态让判断有真值，排产让力气打在约束上，**
