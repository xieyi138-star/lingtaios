# 项目脚手架 · 使用说明

> **开一个新项目 = 复制这个文件夹到项目根目录。方法就装好了。**
> 不是「记得按方法做」，是**方法已经在那里，不做反而费劲**。

---

## 怎么用

```
1. 复制本文件夹 → <新项目>/brain/
2. 打开 01_法典.md，把 §项目专属 那几行填上（地图/红线/阶段目标）
   **首次运行**：把 `状态源.示例.json` 复制为 `状态源.json` 并按项目填真源，
   执行 `python -X utf8 状态生成器.py` —— 自动生成 `02_状态.md / 02_状态.json`
   （⛔ 02 是机器生成物，人手一个数字都不许写；探针未填时生成器会报警且不产出 02——
   属 fail-loud 设计，不静默造零，填好真源再跑）
3. 把 01_法典.md 的路径写进项目指令（CLAUDE.md / Project instructions）
   ⚠ 只写「去读 brain/01_法典.md」，不许把内容抄进去 —— 抄一份就是两份，两份必然分叉
4. 填 00_宪法.md（果的定义 + 好的判据 + 红线 + 回滚阈值）—— 这是锁死层，之后仅人可改
5. 开工。每次开窗按 01_法典.md 的开窗五步走
```

## 三件套：为什么光有 Skill 不够

| 件 | 装什么 | 机制 | 何时加载 |
|---|---|---|---|
| **常驻核** | 三条永不豁免、证据头、开窗五步 | 全局指令 / 项目指令 | **每条消息** |
| **技能** | 四阶段细则、关口、工单模板、进化规格 | `~/.claude/skills/` | **任务匹配时** |
| **脚手架** | 本文件夹 | 复制 | **开项目时** |

**Skill 是按需加载的——它只在描述匹配上时才被读。**
所以它治的是「细则忘了怎么办」，治不了「根本没想起来要按方法做」。
后者只能靠常驻核（每条消息都在）+ 脚手架（文件已经在那儿了）。

---

## 防吃灰的三个真机制（**都不靠记性**）

1. **物理形态约束**：证据头缺了是格式错，一眼可见。软指令在状态差时失效，格式不会。
2. **关口是产物级的，不是记忆级的**：下一阶段需要上一阶段的**产物文件**才能开始
   （没有死因表就进不了施工，没有施工图就不许派工）。忘不掉，因为下一步开不了工。
3. **状态是算出来的**：`状态生成器.py` 每次从真源重算，文档不会烂。
